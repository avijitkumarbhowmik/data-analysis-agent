# Capability: Follow-up Suggestions

_Phase 2._

## What It Does
After each answer, Gemini proposes 2–3 relevant follow-up questions (grounded in the workspace schema + the masked result shape) that the user can click to ask next, carrying prior-turn context via conversation memory.

## Inputs
| Input | Type | Source | Required |
|-------|------|--------|----------|
| question | string | user | yes |
| masked result shape + answer | string | compose_answer / enrich | yes |
| schema_summary (masked) | string | prepare_context | yes |

## Outputs
| Output | Type | Destination |
|--------|------|-------------|
| followups | list of 2–3 strings | API response + `runs.followups_json` + UI chips |

## Contract
`followups = [ string, string, (string) ]` — 2 or 3 plain-language question strings. Never fewer than 2 on success; on failure the field is `[]` (degrade) and the UI shows no chips.

## External Calls
| System | Operation | On Failure |
|--------|-----------|------------|
| Gemini (`gemini-2.5-flash`) | propose follow-ups from masked question + masked result shape + schema | return `[]`, keep answer (degrade) |

## Business Rules
- 2–3 suggestions, grounded in the dataset's real columns (not generic) — only masked schema/shape is sent to the LLM.
- Clicking a chip issues a new ask that carries conversation context (see `conversation-memory.md`).
- Generated by the `enrich` node (owned by `backend-enrich`) via a dedicated prompt in `src/prompts/`.

## Success Criteria
- [ ] Each successful answer returns ≥2 follow-up strings referencing the dataset's columns.
- [ ] Clicking a suggestion asks it with the prior turn in context.
